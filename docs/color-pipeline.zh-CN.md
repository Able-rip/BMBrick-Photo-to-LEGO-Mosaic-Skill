## 1. 问题域

LEGO 1×1 plate（零件号 #3024）在 PAB 上有 42 个颜色。Round 1×1 tile（#98138）有 54 个颜色。任何现代手机拍的照片每像素有 16,777,216 个可能的 RGB 值。LEGO 马赛克生成器的工作就是：拿到这张照片，对 48×48 / 64×64 / 96×96 网格里的每个"像素"，决定放 42（或 54）个物理砖块颜色中的哪一个——并且要做到最终能拼出来的实体马赛克还能看得出原图是什么。

这是一个受约束的颜色量化问题，但有三个性质让标准方案不够用：

1. **目标调色板小且物理固定。** 你没法生成中间色。某个像素在感知空间中"最近"的 LEGO 颜色可能仍然挺远。

2. **空间一致性比逐像素准确度更重要。** 相邻砖块在两个颜色间闪烁看起来像算法 bug。一整块"够接近"的单色看起来像故意的风格化。LEGO 马赛克的美学依赖大块干净的单色区域配合有意识的过渡。

3. **输出是低分辨率渲染。** 48×48 网格总共 2,304 块砖。没有细节余量。每个量化决定在最终成品里都看得见。

朴素的 RGB 距离最近邻量化会在皮肤色调上产生明显色带、渐变变成阶梯式、平坦区域里随机散色。朴素的"先 smooth 再 quantize"会过度平滑然后产生更严重的色带——因为 quantizer 没有足够的中间色可以插值。过去 18 个月里我们尝试过的每个"显而易见的改进"，要么直接失败、要么在测试集的别处引入新病灶。

下面的内容记录了我们 ship 了什么、撤回了什么、以及在 25 个版本迭代里活下来的规则。

### 测试集

每个管线改动都用同一套 13 张参照照片评审：4 张单主体肖像（人+宠物）、2 张多主体肖像（情侣、家庭）、2 张婚礼场景（一张影楼一张户外）、2 张风景、1 张特写物品、1 张故意模糊的输入（负对照）、1 张黑白参考图。每张图打 5 个维度的分（背景一致性、主体细节、渐变质量、砖块美感、平均逐像素色差），并且要求：**回归不超过 15% case、改善超过 30% case、改善/回归比 > 3:1**。在某张精心挑选的图上赢、其他持平的改动不会 ship。

## 2. 当前管线（V25）

```
原始像素
        │
        ▼
┌──────────────────────────────────┐
│ applySharpen(amount = 0.4)       │  Laplacian 边缘增强
└──────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────┐
│ applyToneMap(ceiling = 235)      │  自适应高光压缩
│   97 分位数 → highlightLevel     │  （暗部不动）
│   knee = clamp(hi − 35, 130, 190)│
│   v ≤ knee: 透传                 │
│   v >  knee: sqrt 软肩           │
└──────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────┐
│ bilateralFilter                  │  保边缘平滑
│   radius = 3                     │
│   sigmaSpace = 2.5               │
│   sigmaColor = 20                │
└──────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────┐
│ 逐像素量化                       │  加权 OKLab 距离，
│   weighted OKLab(L weight = 2)   │  对 42 色调色板线性扫描
│   continuityPenalty 0.008        │
└──────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────┐
│ Error-driven F-S 抖动            │  Floyd-Steinberg 误差扩散
│   8% – 100% 强度                 │  强度由逐像素量化距离驱动
│   serpentine 蛇形扫描            │
│   error clamp 每通道 ±60         │
└──────────────────────────────────┘
        │
        ▼
   量化输出
   （马赛克预览、PDF 蓝图、零件清单）
```

### 各阶段细节

**Sharpen（amount = 0.4）** —— tone map 前一次小幅度 Laplacian 锐化。下游 bilateral 和 quantizer 都会轻微柔化图像；预锐化是补偿，让眼睛、鼻孔等"识别地标"能存活到输出。数值再大会在亮边缘出现 halo 伪影；再小会让脸部糊掉。

**Tone map（sqrt 软肩）** —— 压缩高光，不动暗部。由 97 分位数驱动的 knee 自适应输入：亮图被积极压缩、暗图基本不动。sqrt 曲线在 knee 附近很温和，保留高中调对比。`ceiling=235` 这个参数保证最亮的输出值不会越过 quantizer 映射到 White 的阈值，所以猫被照亮的脸会映射到 Tan 或 Light Bluish Gray，不会被一片纯白吞没。

**Bilateral filter（r=3, σs=2.5, σc=20）** —— 在保留边缘的同时平滑平坦区。48–96 像素工作分辨率下，radius=3 窗口总计算量 < 10 万次乘法，几毫秒搞定。曾考虑用高斯模糊（更快、但破坏边缘）替代，被否决——它会消掉 sharpen 步骤要保护的地标。

**Weighted OKLab 量化（L 权重 = 2.0）** —— 距离在 OKLab 感知颜色空间计算，L（亮度）分量加权 2 倍于 a/b（色度）。50 色调色板存在一个扁平 Float32Array 中，每像素线性扫描。L 加权是"马赛克看起来像不像一张脸"的决定因素——人眼在低空间分辨率下对色相偏移的容忍度远高于对亮度偏移。

**continuityPenalty（square plates 0.008，round tiles 0.003）** —— 相邻砖块要分配不同颜色时加的小额外成本。抑制平坦区域里的单像素散色。Round tiles 用低一点的值，因为它们的自然纹理对变化容忍度更高。**这个值是硬下限：** 0.008 以下平坦区会散色，0.002 和 0.005 在测试上无法区分（见 [失败 5.5](#failed-2)）。

**Error-driven Floyd-Steinberg 抖动（8%–100% 强度）** —— 标准 F-S 误差扩散，但扩散强度由逐像素量化距离缩放。调色板匹配良好的平坦区只用约 8% 强度（基本关掉，保持干净色块）。调色板覆盖不好的渐变区用到 100%（全力抖动打破色带）。蛇形扫描（偶数行 L→R，奇数行 R→L）消除方向性伪影。误差 clamp 每通道 ±60。

## 3. 架构决策

下面这些是回头看决定成败的非显而易见选择。每条都经过明确评审才 ship；每条都至少抵御过一次回退尝试。

### 3.1 量化输入是 bilateral 之后的数据，不是原始像素

老版本逐像素量化原始输入，再混入少量平滑结果做一致性。结果是碎裂的色块加随处可见的噪点。

当前管线**先**在整张图上跑 bilateral，得到干净的大色块，**然后**对那个结果量化。量化器看到的输入颜色分布小得多，自然产生更干净的色块。

这一改动是"竞品预览看起来干净、我们以前看起来碎"差距缩小的最大贡献者。

### 3.2 OKLab 距离里 L 权重 2×

人眼在低分辨率下的视觉感知由亮度边缘主导。一张脸的高光/阴影模式被识别出来，远早于色相被解读。L 加权 2 倍于 a/b 的意思是：当被迫在匹配色相和匹配亮度之间选时，永远选亮度。

这条规则曾被撤回一次（V19，42/42 case 回归），后来重新 ship。我们后来发现这条只在配合 sqrt 软肩 tone map 时成立。配合更硬的 tone map 时，L 权重 2× 会过度强调已经被压缩的高光、丢失暗部细节。

### 3.3 永远不要 lift shadow

任何图像管线都有这种诱惑："改进"暗部，把它们抬高 1–3 个 level。我们试过（V4 里的 `v + (v/knee)*3` shadow lift）然后立刻回归：黑色变灰、深色毛发在深色背景里失去对比、叶子阴影变浑浊。

当前管线对任何 ≤ knee 的值直接 `continue`。最暗的输入像素变成最暗的输出砖块。这对"竞品的暗图预览看起来更通透"差距是关键——那个差距是**没做提亮**的结果，不是任何积极的增强。

### 3.4 Bilateral，不是高斯

高斯模糊更快更简单，但 48–96 像素工作分辨率下它会毁掉任何肖像里的眼睛、鼻子、嘴——sharpen 步骤要保护的地标。Bilateral 在 radius=3、σ_color=20 下能保留 20 RGB 单位以上锐度的边缘，同时平滑其他一切。

在我们的工作分辨率下，bilateral 跑得太快（~5ms）以至于"用高斯更快"的论点根本不适用。早期有人提议切高斯，被否决。

### 3.5 对 50 色线性扫描，不是 KD-Tree

50 色调色板存成扁平 Float32Array、逐像素线性扫描，在现代 CPU 上比 KD-Tree 更快。50 个节点的树高大约 6 层，但每层都有一个预测不佳的分支。线性扫描 cache 友好，热路径上没有分支误预测。

这是典型的"更复杂的数据结构反而更慢，因为数据集太小、渐近复杂度不重要"的案例。除非你的调色板有数千个颜色，不要上 KD-Tree。

### 3.6 每次都用同一套 13 张图评审

最重要的元决策是承诺一套固定的 13 图评审集 + 5 轴评分准则。每个量化改动都跑全集，由独立 reviewer 评审（clean context，看不到 changelog 和 playbook，只看分数和 diff PNG）。

我们抓到的每个回归都是因为同样的照片反复跑出来才发现的。好几个看似有希望的改动在 8 个 case 上赢、在 3 个上回归，全集跑出来才看得见。一个修复了你盯了一小时那张图的改动，更多时候会破坏你没检查的其他图。

## 4. 验证过的原则

下面这些规则在多轮迭代和明确的违反尝试里活了下来。每条都标注了它的参数上下文——改了其他参数的管线可能让这些规则失效。

### 4.1 预处理越少，色彩越真实

量化之前的每一步"增强"（auto-levels、色偏校正、vibrance、shadow lift）在测试中都至少回归 7/13 case。量化器需要看到尽可能接近原图的源。预处理的工作只能是边缘保护（sharpen）和噪声去除（bilateral）——**绝不能**"改进"颜色。

### 4.2 配合 sqrt 软肩 tone map 时，L 权重 ∈ [1.5, 2.5] 是对的

在 tone map 使用 ceiling=235 的 sqrt 软肩时，L 权重 2.0 在 13/13 case 上赢过 1.0。配合激进的 tone map（ceiling < 220 或硬 knee），L 权重 2.0 反而**输**——高光本来就被压缩了，L 加权高只是让损失更严重。规则的成立有条件。

### 4.3 不要 lift shadow

每张暗区测试图都验证过。"竞品的暗图看起来更好"的差距完全是"没 bug"——他们不 lift shadow，我们以前会。

### 4.4 这个分辨率下 bilateral 胜过高斯

48–96 像素工作分辨率下，保边缘是不可商量的。Bilateral 在 r=3、σ_color=20 是甜点。σ_color < 15 噪声穿透；σ_color > 25 过度平滑、产生**更多**色带（见 [失败 5.4](#failed-4)）。

### 4.5 Serpentine 扫描消除方向性伪影

单独 F-S 误差扩散会产生一个隐约可见的对角伪影模式。按行交替扫描方向（奇数行 kernel 镜像）能不调任何参数消除这个问题。8/13 case 改善，0 回归。

### 4.6 continuityPenalty 在 0.008 有硬下限

square plates 上。低于这个值 quantizer 失去抑制平坦区单像素散色的能力。0.008 以下的两个值（0.002 和 0.005）测试上无法区分地差。Round tiles 允许 0.003 因为自然纹理吸收变化。**高于** 0.012 会开始过度约束渐变区。

### 4.7 Error-driven 抖动胜过 edge-based

老版本用局部色差（edge-based 信号）检测"渐变区域"再在那里抖动。这个在太多假区域被触发。当前用逐像素量化距离作为抖动触发：如果最近的调色板颜色在 OKLab 空间里远，就激进抖动；如果近，就放过。这能正确识别真正需要抖动的区域（即调色板覆盖不到源色的地方）。

### 4.8 误差在 RGB 空间扩散可接受

考虑过在 OKLab 空间扩散误差（感知上更准）。实现成本高（RGB → OKLab → 扩散 → OKLab → RGB），测试集上没看到明确收益。RGB 空间扩散在实践中够用。

## 5. 失败实验清单

每条按统一格式：**改动是什么** / **预期** / **实际发生了什么** / **根因** / **教训**。下面是 25 版迭代里最有信息量的失败。

<a id="failed-1"></a>
### 5.1 S-Curve 1.15

**改动。** 量化前 `applySCurve(data, 1.15)`，目的是小幅提升对比度。

**预期。** mid-tone 浑浊减少 ~5–10%。

**实际。** 猫脸几乎全白。RGB 200–230 的高光被推到 245–255，量化时全部映射到 White。

**根因。** S-Curve 公式对其对比度参数是非线性的：`1.15` 输入产生 1.79 倍有效对比度。函数命名暗示线性，数学不是。

**教训。** 当一个函数有"强度"参数时，先把输入→输出转移函数画出来再相信那个数字。每个可调滤镜在画图之前都是不透明的。

<a id="failed-2"></a>
### 5.2 `const smoothData = originalData`

**改动。** 严格说什么都没改——一行看起来无害的代码。

**预期。** smoothing 步骤在量化前模糊低频区域。

**实际。** 到处散色。本该是一块纯色的背景碎成 4–5 块带噪点的小块。

**根因。** 几个月前的一次重构注释掉了真正的 smoothing 调用，换成 `const smoothData = originalData`。下游 `blendQuantizationSample(working, smooth)` 现在是把图跟自己混合——一个 no-op。

**教训。** 给非平凡变量做 identity 赋值是代码异味。现在我们显式断言中间阶段产生了可测量的变换：`assert(distance(smoothed, original) > threshold)`。

<a id="failed-3"></a>
### 5.3 Bayer 有序抖动

**改动。** 在渐变区用 Bayer 8×8 有序抖动替代 Floyd-Steinberg 误差扩散。

**预期。** 更干净的渐变 + 结构化纹理。

**实际。** 6/6 reviewed case 的每个渐变区都更差。Bayer 8×8 pattern 在 48–96 像素分辨率下肉眼可见。

**根因。** Bayer 矩阵是为高分辨率显示设计的，pattern 在那里会消融成感知平滑。8×8 pattern 在 48×48 网格里占 16% 面积——读起来是规则的点阵，不是平滑。LEGO 马赛克美学依赖大块干净色块；任何破坏它的东西看起来像算法故障。

**教训。** 在一个分辨率上赢的算法可能在另一个上完全失败。"抖动减少色带"的成立条件是 pattern-to-pixel ratio。

<a id="failed-4"></a>
### 5.4 Bilateral filter σ_color = 35

**改动。** bilateral `sigmaColor` 从 20 提到 35，更强平滑。

**预期。** 输入更平滑 → 量化更干净 → 色带更少。

**实际。** 色带**反而**更严重。7/13 case 回归。

**根因。** 更强的 bilateral 把更多相邻但不同的颜色合并掉。σ_color=20 时皮肤区有 ~80 个不同的 RGB 聚类，量化器有充分变化分布到 6 个可用的 LEGO 肤色上。σ_color=35 时这些塌缩到 ~30 个聚类，量化器没有中间值可以插值，只能选最近的两个 LEGO 颜色，产生硬色带。

**教训。** "平滑输入"不总是量化的赢面。量化器需要**足够**的不同颜色才能选出聪明的过渡。

<a id="failed-5"></a>
### 5.5 continuityPenalty 0.002 和 0.005

**改动。** continuityPenalty 从 0.008 降到 0.002。回归后试 0.005 作为"折中"。

**预期。** 更低的 penalty → 更自由的渐变 → 更平滑的过渡。

**实际。** 两个值都回归，几乎完全一样。0.002 vs 0.005 之间的 avgErr 差异 < 0.001——统计上是平局。

**根因。** continuityPenalty 不是连续的旋钮，是一个开关。Error-driven dithering 在逐像素量化误差超过阈值时激活，而平坦区的误差**也**很高（调色板不能完美覆盖所有 RGB 空间）。continuityPenalty 是唯一抑制激活的东西。低于 0.008 就把开关关了。

**教训。** 当一个参数的两个值产生相同的坏结果时，问题不在这个参数。看看 pipeline 里别的什么在发生。

### 5.6 L 权重 2×（ship → unship → re-ship 的传奇）

**改动。** OKLab 距离里 L 分量加权 2×，回归后撤回，后来又重新 ship。

**预期。** 低分辨率下更好的感知匹配。

**实际。** 在大部分测试集上赢，V19 上 42/42 回归，tone map 改动之后又赢了。

**根因。** L 权重 2× 跟 tone-map 的激进度有交互。配合硬 tone map 时，L 权重高会过度强调已被压缩的高光、丢失暗部细节。配合 sqrt 软肩时这个交互是良性的。

**教训。** 图像管线里的"总是"和"绝不"通常是错的。正确的框架是"当其他参数也是 X 时，这条原则成立"。我们在这条上被烫过两次。

### 5.7 "AI 帮我重写的 V4"——堆叠副作用

**改动。** 一个独立的保真度渲染管线（"V4"），带三个独立压暗模块：tone-map 高光、底板轻微压暗、亮色砖块上的 stud 调暗。

**预期。** 物理效果干净地叠加。

**实际。** 一切都灰了。颜色距离函数开始偏好灰色砖块。黑色网格线视觉上变粗。饱和的红黄失去 pop。

**根因。** 三个模块各自假定自己是唯一在跑的那个。Tone-mapper 在正常曝光假设下压高光。底板补偿在高光未动假设下压所有砖块。Stud 调暗在底板没动假设下调暗亮色砖块。三个在隔离下都对。叠起来在亮区产生 ~0.20 的有效亮度——一个没人设计的 5× 压暗。

V5 试图用调参修复。V5 引入高光过曝。V5.1 重调引入白砖色偏。整个分支最后被丢掉。

**教训。** 堆叠的乘性效果，每个单独"有道理"，叠起来不会 compose。Pipeline 需要一个地方拥有最终的亮度/对比度包络，每个子阶段必须声明它对其他阶段输出的假设。

### 5.8 量化后用 guided filter 去噪

**改动。** 对量化输出应用 guided filter 清理散色。

**预期。** 最终马赛克的区域更平滑，不用重新量化。

**实际。** 没有可见改进。Guided filter 在连续色空间操作，但输出已经映射到离散砖块颜色了。任何"改进"会被再次离散化回到同一个砖块调色板。

**根因。** 量化后去噪必须在离散调色板空间操作。当作连续域问题处理会让滤波不可见。

**教训。** 数据一旦离散化，对它的连续域操作没有效果，除非你**同时**改变离散化。Block-anchor（4×4 多数投票在离散调色板里）有效得多。

### 5.9 Gemini V6 ——"少即是多"过了头

**改动。** 去掉 tone map + sharpen + shadow lift。bilateral 降到 r=2、σ_color=15。OKLab 距离无权重。

**预期。** 跟"预处理越少"原则一致的更干净管线。

**实际。** 阴影失去深度，渐变过于均匀，细节消失。

**根因。** "预处理越少"原则在方向上对，但 V6 把它推过了生产性的点。**一些**预处理（保边缘的 sharpen、保高光的轻 tone map）在这个分辨率下是必要的。

**教训。** 大部分原则是局部极值。继续推总会最终回归。永远要问的是"这个还能推多远？"，不是"该不该做这个？"。

### 5.10 Block anchor 权重 0.6+

**改动。** Block-anchor 正则化（4×4 多数投票）用更高权重强制更多空间一致性。

**预期。** 更干净的大色块。

**实际。** 背景锁正确了但主体细节被毁——眼睛、鼻孔、高频特征被 4×4 投票平均掉。

**根因。** Block anchor 必须弱到不会覆盖真正的高频信号。权重 0.40 + despeckle 是甜点。

**教训。** 空间正则化是"小剂量"工具。剂量大会杀掉你想保护的信号。

### 5.11 单独 Despeckle（不带 block anchor）

**改动。** 应用形态学 despeckle（单像素清理）作为独立步骤。

**预期。** 从平坦区移除孤立的噪声像素。

**实际。** 移除了真实细节——眼睛里的小高光、毛发上的稀疏纹理、背景里的小色块。

**根因。** 单独 despeckle 没法区分噪声和有意细节。配合 block anchor（提供空间上下文）才有效，因为 despeckle 只清理跟它所在块的共识不一致的像素。

**教训。** 两种技术可以是互补的——单独哪个都没用。在测试集上交叉验证抓到了这个——单独 despeckle 在细节丰富的图上回归。

## 7. 参数敏感度速查

给想调自己 pipeline 的工程师，这是各参数在我们 setup 里对扰动的敏感度：

| 参数 | 安全范围 | 范围外的失败模式 | 当前值 |
|---|---|---|---|
| continuityPenalty（square） | 0.008 – 0.012 | <0.008：平坦区散色。>0.012：渐变过度平滑 | 0.008 |
| continuityPenalty（round） | 0.003 – 0.005 | 同上，容忍度更宽 | 0.003 |
| OKLab L 权重 | 1.5 – 2.5 | <1.5：暗部噪点。>2.5：高光塌缩 | 2.0 |
| bilateral sigmaColor | 18 – 25 | <15：噪声穿透。>25：更多色带（反直觉） | 20 |
| bilateral radius | 2 – 3 | 两侧效果都很小 | 3 |
| bilateral sigmaSpace | 2.0 – 3.0 | 边际 | 2.5 |
| ToneMap ceiling | 230 – 240 | >245：高光过曝。<225：中调变平 | 235 |
| Dithering strength | 0.30 – 0.50 | 高 = 噪点。低 = 色带 | 0.38 |
| Error clamp（每通道） | ±30 – ±60 | 边际效应 | ±60 |
| Sharpen amount | 0.30 – 0.50 | 高 = halo。低 = 糊 | 0.40 |
| Block anchor 权重 | 0.30 – 0.50 | >0.5 杀细节。<0.3 不锚定 | 0.40 |

**最敏感的参数**是 continuityPenalty（0.008 是硬悬崖）和 bilateral sigmaColor（甜点在 20）。其他参数在安全范围内宽容。

## 8. 未结题 & 未来探索

下面这些是我们评估过但还没 ship 的探索，附当前状态。

### 8.1 Region-adaptive dithering（REFINE）

把每个像素分类为 flat / gradient / detail，每类用不同的 dithering 策略。当前实现（region-adaptive-v3）在 clean-context review 里 9/13 case 改善、0 回归，但大部分改善在背景区域；主体细节平均只 +0.1。还不够 confident ship——需要在 medium-complexity 人像的脸、眼睛、毛发、衣服边界上证明价值。

### 8.2 OKLab 空间误差扩散

在 OKLab 空间而不是 RGB 计算和扩散 F-S 误差。感知上更准但实现成本高（RGB → OKLab → 扩散 → OKLab → RGB 转换开销）。初步测量没有明确赢；暂不计划。

### 8.3 每图最优子调色板（Wu's algorithm）

对每张输入图，动态从完整 42 色集中选最优子调色板，然后对子调色板量化。理论上改善颜色分配效率。实现推迟——当前的逐图颜色计数已经自然适应（稀有调色板颜色很少被选）。

### 8.4 平坦区域专用 Bayer-tile 纹理

重访 Bayer dithering 实验（5.3），但只在已验证的平坦区应用、强度低得多。会增加有意的微纹理而不破坏干净色块美学。还没测。

## 9. 术语表

**量化（Quantization）** —— 把连续输入值（这里是 16M RGB 颜色）映射到有限输出集（这里是 42 个 LEGO 颜色）。

**OKLab** —— Björn Ottosson 设计的感知均匀颜色空间。OKLab 里的距离跟感知颜色差异相关性好。这里用于最近颜色搜索。

**CIEDE2000** —— 更早的感知颜色距离度量，比 OKLab 复杂。我们最初用 CIEDE2000，迁移到 weighted OKLab；感知质量相当，OKLab 更简单更快。

**Bilateral filter** —— 保边缘平滑滤波。像素跟邻居平均，但平均由空间距离和颜色相似度共同加权，所以边缘（锐利色变）被保留。

**Floyd-Steinberg dithering** —— 经典误差扩散技术。像素真实颜色与量化颜色之间的误差按权重（7/16 右，3/16 下左，5/16 下，1/16 下右）分发给邻居未量化像素。

**Serpentine 扫描** —— 对 Floyd-Steinberg 的修改，交替行按交替方向扫描，误差分发 kernel 镜像。消除标准左到右 F-S 的对角伪影。

**continuityPenalty** —— 相邻像素要分配不同颜色时加在逐像素颜色决策上的额外成本。用于抑制平坦区域的单像素散色。

**Block anchor** —— 空间正则化技术，局部 4×4（或类似）块投票一个主导颜色，单个像素被以某种权重拉向那个颜色。在平坦区改善空间一致性。

**Magic Cut** —— 浏览器内 ONNX 模型背景移除。在肖像主体上将零件数减少 60–70%，用单一砖块色替换背景。

**Tone map** —— 把输入亮度映射到输出亮度的函数，通常用于压缩高光或提亮暗部。我们的管线只对高光用 sqrt 软肩曲线。
